# 07 — Open questions

Unresolved design decisions. If you hit one of these mid-build, do not resolve it
silently in code — record the answer here and update the affected doc.

Each entry names what depends on it, so the cost of deferring is visible.

---

## 1. Who owns a finding that turns out to be wrong?

**The question.** If an evaluator scores a student down based on a RepoMan
finding that is later shown to be incorrect, what does the appeals process look
like, and what does RepoMan owe it?

**Why it blocks things.** It decides whether the evidence packet is stored
**immutably** (append-only, every version retained, a correction is a new record)
or as a **living document** (findings can be amended in place). That is a schema
decision, and it hardens fast.

**Lean.** Immutable. `RunManifest` already implies it, and "the packet as it was
at the time of the decision" is the only thing an appeal can actually examine.

**Settle before:** Day 1 exit.

---

## 2. Does the student ever see RepoMan's output directly?

**The question.** Is the student-facing feedback report generated by RepoMan and
sent, or drafted by RepoMan and forwarded by the evaluator after editing?

**Why it blocks things.** It changes the tone of every generated sentence. A
finding written for an evaluator can say "only two roles detected, report claims
five." A finding written for a student needs to be feedback, not an accusation.
If both audiences exist, we need two renderings of every finding, which is a
prompt and schema change.

**Lean.** Evaluator-forwarded for v1, with the student rendering as a separate
export pass rather than a second field on `Finding`.

**Settle before:** the export work on Day 3.

---

## 3. How much repo does a very large submission actually get?

**The question.** A 200,000-file monorepo submission cannot be fully retrieved
per requirement. What is the retrieval budget, and how is it allocated?

**Why it blocks things.** "We truncated silently" is not an acceptable answer —
it violates the honesty invariant. Whatever the policy, the finding must record
what was excluded, which means the budget decision shows up in the `Finding`
schema.

**Options.** Fixed token budget per requirement; adaptive budget by rubric
weight; two-stage retrieval that widens only when the first pass finds nothing.

**Lean.** Two-stage, with the exclusion recorded either way.

**Settle before:** the first submission that is genuinely large. Put a size
fixture in `fixtures/` early so this is not discovered during the demo.

---

## 4. Cross-institution similarity

**The question.** Similarity detection is far stronger across institutions than
within a single cohort — the same template submitted at three universities is
invisible to any one of them.

**Why it is deferred.** It is a data-sharing conversation, not a technical one:
whose submissions, under what agreement, retained how long. Out of scope for v1,
in scope for the vision.

**Settle before:** any conversation with a second institution.

---

## 5. What counts as a "requirement" when the rubric is holistic?

**The question.** Some rubrics are not itemized at all — "overall engineering
quality, 40 marks." The compiler can decompose it, but the decomposition is then
RepoMan's opinion rather than the evaluator's rubric.

**Why it matters.** It quietly moves judgment from the human to the system, which
is exactly what the thesis forbids.

**Lean.** Decompose, but present the decomposition for explicit approval before
the run, and mark it as RepoMan-proposed rather than evaluator-authored in the
`Requirement` record. That probably needs a field.

**Settle before:** the rubric compiler is considered done.

---

## 6. Do deterministic and model-derived evidence carry equal weight in the UI?

**The question.** `Evidence.provenance` distinguishes them. Should the workspace
visually rank a probe result above a model result?

**Lean.** Yes, show provenance — evaluators should know which parts of the system
are not guessing. But do not let it collapse into "ignore the model findings,"
which would waste most of the value.

**Settle before:** the evidence panel is built on Day 2.
